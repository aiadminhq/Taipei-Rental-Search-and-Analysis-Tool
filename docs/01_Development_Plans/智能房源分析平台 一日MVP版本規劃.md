# 個人租屋分析工具 一日開發計劃

**版本**: 個人版 1.0
**開發時間**: 8小時 (一個工作日)
**目標**: 快速建立個人使用的租屋分析工具

---

## 執行摘要

這是一個專為個人租屋需求設計的簡單工具，核心理念是"簡單實用，快速上手"。在8小時內建立一個能夠：

1. **多元輸入**：支援 591 等租屋網站連結、截圖上傳、智能搜索
2. **AI 分析**：使用 Claude + Gemini Pro 2.5 進行房源評分和分析
3. **本地存儲**：使用瀏覽器本地存儲，無需複雜的資料庫
4. **手機優化**：響應式設計，手機和電腦都能使用
5. **快速部署**：Replit 一鍵部署，30分鐘內上線

這個工具專注於解決個人租屋時的核心痛點：快速篩選房源、AI 智能評分、簡單的資料管理。

### 2.2 數據模型設計

MVP版本的數據模型保持簡單，只包含核心的業務實體和關係。

#### 2.2.1 房源數據模型

**Properties表結構**
```sql
CREATE TABLE properties (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title VARCHAR(200) NOT NULL,
    address VARCHAR(300) NOT NULL,
    district VARCHAR(50) NOT NULL,
    rent_price INTEGER NOT NULL,
    room_type VARCHAR(20) NOT NULL,
    area_size DECIMAL(6,2),
    floor_info VARCHAR(50),
    building_age INTEGER,
    description TEXT,
    contact_info VARCHAR(200),
    image_urls TEXT,
    latitude DECIMAL(10,8),
    longitude DECIMAL(11,8),
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

這個表結構包含了房源的基本信息，足以支援MVP版本的功能需求。image_urls字段存儲JSON格式的圖片URL列表，latitude和longitude字段為未來的地圖功能預留。

#### 2.2.2 統計數據模型

**Statistics表結構**
```sql
CREATE TABLE statistics (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    stat_type VARCHAR(50) NOT NULL,
    district VARCHAR(50),
    room_type VARCHAR(20),
    stat_value DECIMAL(12,2) NOT NULL,
    stat_date DATE NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

統計表用於存儲預計算的統計數據，如各區域平均租金、房源數量等。這種設計可以提高查詢性能，避免實時計算。

### 2.3 API設計規範

MVP版本的API設計遵循RESTful原則，提供簡潔明確的接口。

#### 2.3.1 房源相關API

**GET /api/properties**
搜尋和篩選房源的主要接口。支援以下查詢參數：
- keyword: 關鍵字搜尋
- district: 行政區篩選
- min_price, max_price: 價格範圍
- room_type: 房型篩選
- min_area, max_area: 面積範圍
- sort: 排序方式 (price_asc, price_desc, date_desc)
- page, limit: 分頁參數

**GET /api/properties/:id**
獲取特定房源的詳細信息，包括完整的描述、圖片、聯絡方式等。

#### 2.3.2 統計分析API

**GET /api/statistics/overview**
獲取市場概覽數據，包括總房源數、平均租金、各區域分佈等。

**GET /api/statistics/districts**
獲取各行政區的統計數據，支援區域比較功能。

**GET /api/statistics/trends**
獲取租金趨勢數據，返回最近3個月的價格變化。

## 3. 用戶體驗設計

### 3.1 用戶流程設計

MVP版本的用戶流程設計注重簡潔性和直觀性，確保用戶能夠快速上手並完成核心任務。

#### 3.1.1 主要用戶流程

**房源搜尋流程**
用戶進入網站後，首先看到的是搜尋頁面。頁面頂部有一個醒目的搜尋框，用戶可以輸入關鍵字進行搜尋。搜尋框下方有基本的篩選選項，包括價格範圍、房型、區域等。用戶設定搜尋條件後，點擊搜尋按鈕，系統返回符合條件的房源列表。

房源列表以卡片形式展示，每個卡片包含房源的關鍵信息。用戶可以快速瀏覽列表，點擊感興趣的房源查看詳情。詳情頁面提供房源的完整信息，包括圖片、描述、周邊環境等。

**數據分析流程**
用戶可以通過導航欄進入數據分析頁面。頁面首先展示市場概覽，包括關鍵統計數據和圖表。用戶可以選擇特定的區域或房型查看更詳細的分析。分析結果以圖表和表格的形式展示，用戶可以直觀地了解市場趨勢。

#### 3.1.2 錯誤處理流程

**搜尋無結果處理**
當用戶的搜尋條件過於嚴格導致無結果時，系統會顯示友好的提示信息，並建議用戶調整搜尋條件。系統會分析用戶的搜尋條件，提供具體的調整建議，如擴大價格範圍或選擇鄰近區域。

**網路錯誤處理**
當發生網路錯誤或服務器錯誤時，系統會顯示清晰的錯誤信息，並提供重試選項。對於暫時性的錯誤，系統會自動重試；對於持續性的錯誤，系統會建議用戶稍後再試。

### 3.2 界面設計原則

#### 3.2.1 簡潔性原則

MVP版本的界面設計遵循簡潔性原則，避免不必要的視覺元素和複雜的交互。每個頁面都有明確的主要任務，界面元素圍繞這個任務進行組織。

**色彩設計**
使用簡潔的色彩方案，主色調為藍色系，體現專業性和可信度。輔助色彩包括綠色（表示正面信息）和橙色（表示警示信息）。背景主要使用白色和淺灰色，確保內容的可讀性。

**字體設計**
使用系統默認字體，確保在不同設備上的一致性。字體大小遵循清晰的層次結構，標題使用較大字體，正文使用適中字體，輔助信息使用較小字體。

**佈局設計**
採用網格系統進行佈局，確保元素的對齊和一致性。重要信息放在顯眼位置，次要信息適當弱化。使用充足的留白來提高可讀性。

#### 3.2.2 響應式設計

**桌面端設計**
桌面端採用多欄佈局，充分利用大屏幕的空間。搜尋和篩選功能放在左側，房源列表放在中間，地圖或統計信息放在右側。這種佈局讓用戶可以同時查看多種信息。

**移動端設計**
移動端採用單欄佈局，功能按優先級垂直排列。搜尋功能放在頂部，篩選功能可以摺疊，房源列表垂直滾動。所有的交互元素都有足夠的觸控面積。

**平板端設計**
平板端介於桌面端和移動端之間，根據屏幕方向動態調整佈局。橫屏時採用類似桌面端的多欄佈局，豎屏時採用類似移動端的單欄佈局。

### 3.3 交互設計細節

#### 3.3.1 搜尋交互

**搜尋框設計**
搜尋框採用醒目的設計，放在頁面的顯眼位置。搜尋框內有提示文字，幫助用戶理解可以搜尋的內容。用戶輸入時，系統提供自動完成建議，幫助用戶快速輸入。

**篩選交互**
篩選選項採用直觀的控件，如下拉選單、滑動條、複選框等。用戶修改篩選條件時，系統實時更新搜尋結果，提供即時反饋。篩選條件可以重置，方便用戶重新開始搜尋。

**結果展示交互**
搜尋結果支援多種排序方式，用戶可以根據需要選擇。結果列表支援分頁，避免一次載入過多數據影響性能。用戶可以快速返回搜尋結果，無需重新搜尋。

#### 3.3.2 數據可視化交互

**圖表交互**
統計圖表支援基本的交互功能，如懸停顯示詳細數據、點擊切換數據系列等。圖表的設計簡潔明了，避免過於複雜的視覺效果。

**數據篩選交互**
用戶可以選擇不同的時間範圍、區域範圍來查看統計數據。篩選控件設計直觀，用戶可以輕鬆理解和操作。數據更新時有適當的載入提示。
