# Claude Design 提示詞包：TRSAT 租屋收件匣 PWA 原型介面

**日期**：2026-09-05
**用途**：在 Claude Design（或任何以自然語言產生 UI 原型的工具）中，依序貼上以下提示詞，產出與 `docs/superpowers/specs/2026-09-05-pwa-rental-mvp-design.md` 第 7 節一致的高擬真原型。
**使用順序**：先貼「P0 系統提示（設計系統）」建立整體語言，再逐一貼 P1–P7 畫面提示；每個畫面完成後再貼 P8 元件表與 P9 流程圖；最後用 P10 做深色模式與交付標註。
**注意**：所有範例資料皆為虛構（電話一律 `0912-000-xxx`），不得使用真實房源或個資。

## P0 系統提示：產品定位與設計系統（先貼這一段）

```
你是資深 mobile product designer。接下來我會逐張請你設計一個 PWA 的畫面，請先把以下設計系統記住，之後每張畫面都要遵守，不要每次重新發明樣式。

【產品】TRSAT 租屋收件匣。單人使用的 local-first PWA，幫一位在台北找房的使用者把從 591、Threads、Facebook 社團、PTT 看到的房源，用「分享」或「貼上」送進 App，立刻依個人條件分成三級：符合／待確認／不符，再追蹤看房進度。沒有登入、沒有雲端帳號、資料只存在手機。

【使用者】一位 30 歲左右的專案經理／介面設計師，養兩隻貓，預算雅房約 1 萬、套房約 1.5 萬，要台北或新北、走到捷運 15 分內、必備變頻冷氣／冰箱／對外窗／洗衣機，謝絕壁癌、無對外窗、壁紙、隔音差。心智模型像 email 收件匣：東西先進來，再決定留或丟。

【核心原則】
1. 收件匣心智模型：分享當下只做「加入／略過」兩個決定，不填表。
2. 三色分級就是資訊架構：所有清單都先依分級排序。符合＝綠、待確認＝琥珀、不符＝灰且預設收合。
3. 單手操作：底部 4 個 Tab，主要動作放在拇指區，觸控目標最小 44×44 px，卡片可左右滑動。
4. 離線是正常狀態：不顯示「無網路」錯誤，只在需要補資料的欄位標「待電腦補抓」。
5. 白話文案，繁體中文，術語保留英文。

【Design tokens】
- 畫布：iPhone 15 / 390×844，含 status bar 與底部 home indicator 安全區。
- 字體：Noto Sans TC。標題 20/700、卡片主數字 24/700、內文 14/400、輔助 12/400、標籤 11/500。
- 主色 primary：#3b82f6。只用於主要按鈕、選中 Tab、連結。
- 分級色：pass #16a34a、unknown #d97706、fail #6b7280。分級色只用在 TierBadge、檢核清單圖示、卡片色點，不當背景大面積使用。
- 中性色：背景 #f9fafb、卡片 #ffffff、邊框 #e5e7eb、主文字 #111827、次文字 #6b7280。
- 圓角：卡片 12、按鈕 10、chip 999、輸入框 8。
- 陰影：卡片 0 1px 2px rgba(0,0,0,.06)。
- 間距：8 的倍數；頁面左右邊距 16。
- 圖示：Lucide 線性圖示 20px，不用 emoji 當功能圖示（Tab 例外可用簡潔線性圖示）。

【固定元件詞彙】之後我提到這些名字時請沿用同一個樣式：
- BottomNav：4 Tab，依序「收件匣」「房源」「比較」「設定」；收件匣有未處理數量 badge。
- TierBadge：圓角膠囊，白字，底色為分級色，文案「符合／待確認／不符」。
- ListingCard：三行卡片。第一行左側租金大字（NT$14,500）＋右側 TierBadge 與狀態 chip；第二行「大安區 · 套房 · 8坪 · 捷運 6 分」；第三行來源標籤（591／Threads／FB 社團／PTT）＋最多 3 個設備 tag，或紅字「缺洗衣機」。
- RuleChecklist：逐條檢核，圖示 ✓（綠）／?（琥珀）／✗（紅）／＋（藍，加分），後接一句原因，例如「租金 14,500 在預算內」「未提及洗衣機」「含「壁癌」」。
- FilterChip：可橫向捲動的膠囊 chip，選中時 primary 底白字。
- StatusStepper：橫向可捲動 chip 列，狀態依序：候選 → 已聯絡 → 約看房 → 已看房 → 淘汰／已簽約。
- PasteSheet：底部彈出的 bottom sheet，含大 textarea、「從剪貼簿讀取」與「解析」兩個按鈕。
- Toast：頂部居中深色膠囊，可帶一個動作按鈕（例：「有新版本可用 ［更新］」）。

請先回覆「已載入設計系統」，不要先畫任何畫面。
```

## P1 畫面：分享接收頁（S1 Share）

```
畫面 1：分享接收頁（路由 #/share）。這是使用者在 591 App 或 Threads 按「分享 → 租屋收件匣」之後，第一個看到的畫面。目標：3 秒內讓使用者看懂「這間房被判為什麼等級、為什麼」，然後按一個按鈕。

版面（由上到下）：
1. 頁首：小標「收到房源」，右上角小字顯示來源標籤「Threads」。
2. 預覽卡（PreviewCard，佔畫面主要區域）：
   - 卡片頂列：來源 chip「Threads」左、TierBadge「符合」右。
   - 標題（最多兩行）：「#出租 大安區獨立套房 近科技大樓站」
   - 租金大字：NT$14,500，後接小字「/月」。
   - 三格可編輯欄位並排：租金［14500］、區［大安區 ▾］、房型［套房 ▾］。已偵測到的欄位灰底顯示；未偵測到的欄位以琥珀色虛線框並標「未偵測到，請補」。
   - 精簡版 RuleChecklist，只列非 ✓ 的項目，最多 3 條，例如：「? 未提及洗衣機」「＋ 有電梯」。若全部符合顯示灰字「全部條件符合」。
3. 卡片下方一行 12px 琥珀色提示（只在解析信心不足時出現）：「解析信心不足，請至少補一個必要欄位後再加入。」
4. 三個等寬按鈕一列，固定在畫面下方拇指區：「略過」（外框）、「先放收件匣」（外框）、「加入房源」（primary 實心）。信心不足時「加入房源」為 disabled 樣式（40% 透明）。
5. 最底部一個可展開的「原文」摺疊區，展開後顯示貼文全文（等寬字、保留換行）。

請一次產出三個狀態並排：
A. 高信心（Threads 貼文，全部欄位齊全，TierBadge 符合）
B. 低信心（只分享了 591 連結，沒有文字，三個欄位都是「未偵測到」，加入按鈕 disabled，TierBadge 待確認）
C. 不符（FB 社團貼文含「不可養寵物」，TierBadge 不符，檢核第一條為「✗ 不可養寵物」）

範例原文（狀態 A 用）：
#出租 大安區獨立套房
租金 14,500/月 含管理費，押二付一
約 8 坪，1房1衛，5F/7F 有電梯
變頻冷氣、冰箱、洗衣機、對外窗採光好
捷運科技大樓站 步行 6 分
可養貓 限一隻
洽 0912-000-001
```

## P2 畫面：收件匣（S2 Inbox）

```
畫面 2：收件匣（路由 #/inbox，BottomNav 第一個 Tab 選中，badge 顯示 3）。

版面：
1. 頁首：大標「收件匣」左，右側外框小按鈕「貼上文字或連結」。
2. 卡片流：每一項是一張 PreviewCard（同畫面 1 的卡片，但不含可編輯欄位，只顯示值），卡片下方兩個等寬按鈕「略過」（外框）「加入」（primary）。卡片本身支援左右滑動：請畫出其中一張正在往右滑、露出綠色「加入」提示背景的中間狀態，另一張往左滑露出灰色「略過」。
3. 三張範例卡片：
   - Threads｜大安區套房 NT$14,500｜符合
   - 591｜信義區套房 NT$16,000｜待確認（未提及寵物）
   - PTT｜中和雅房 NT$8,000｜不符（限女生）
4. 空狀態版本：虛線外框卡片，居中兩行說明：「從 591 / Threads / FB 分享到此 App，房源會先出現在這裡。」「iPhone 請複製內容後點右上角『貼上文字或連結』。」下方一個 primary 按鈕「貼上文字或連結」。

另外畫出 PasteSheet 展開狀態：底部 bottom sheet 覆蓋約 55% 高度，標題「貼上連結或貼文」，右上 ✕，中央 160px 高 textarea（placeholder：貼上 591 / Threads / FB / PTT 連結，或整段貼文文字），底部兩個等寬按鈕「從剪貼簿讀取」（外框）「解析」（primary，textarea 為空時 disabled）。sheet 下緣要留 home indicator 安全區。

請產出：有內容（含兩張滑動中卡片）、空狀態、PasteSheet 展開，三張並排。
```

```

   ✓ 租金 14,500 在預算內
   ✓ 可養寵物
   ✓ 台北市大安區
   ✓ 捷運步行 6 分
   ✓ 變頻冷氣　✓ 冰箱　✓ 對外窗　✓ 洗衣機

第三個變體：編輯模式。關鍵資訊格全部變成輸入框／下拉，右上按鈕變「儲存」。

三張並排。
```

## P7 畫面：首次啟用 Onboarding（3 步）
